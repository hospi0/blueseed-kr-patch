## 대사 `MES/S*.MES` (79개) — `tools/mes.py`
- **SJIS 아님** — 세이브스테이트 RAM 어디에도 SJIS 대사 없음. 장면마다 자체 글자 번호.
- 머리 = u32 BE 오프셋 목록 … `FFFFFFFF`. **7번째 칸(hdr[6]) = 메시지 표**(79개 모두 같은 규칙으로 읽힘).
  - 머리 뒤 `[오프셋][크기]` 쌍 표 = 그림(얼굴 등, 크기 0x1E8x 대).
- 메시지 표 = `[u32 오프셋][u32 크기] × N`, 오프셋은 표 시작 기준, 첫 오프셋/8 = N, 조각 2바이트 정렬.
- 본문: `FF xx` 제어(FF FE 가 가장 많음) · `00‥7F` 1바이트 글자 · `80‥FF xx` 2바이트 글자 = `((c&0x7F)<<8|b)+0x80`.
  - 1·2번은 제어일 가능성(가장 많음) — 확인 필요.
- 분량: 메시지 2,825 · 글자 약 22만(중복 포함, 어림).
- 세이브스테이트 1·2: S01_001.MES 가 통째로 Low RAM **0x291500**. MESSAGE.FIX 는 0x2F43A8.

## 글꼴
- **MES 파일 끝에 그 장면 글자만 빈도순 16×16 1bpp(32B/자)** — 파일당 최대 649자(S01_001).
  앞에 8×16 반각 숫자·영문 구역(S01_001 은 0x29178 에 머리 `8, 16, 16, …`).
- → 한글화 = 파일마다 번역문 음절로 글꼴을 새로 만들고 번호를 다시 매긴다(코드 수정 없을 가능성 큼).
- 실행 파일 `/0` 안에도 빈도순 공통 글꼴 약 560자(`0xA6B78` 부근) — 메뉴·전투 등 시스템 글자로 추정.
- VDP2 에는 8×16 영문 글꼴만.
- `MESSAGE.FIX` 는 글꼴이 아니라 `[오프셋][크기]` 그림 묶음(창 테두리 등 추정).

- **번호 ≥ 0x33 → 전각 칸 (번호 − 0x33)**. 0x32 = 공백(추정), 0x00 = 메시지 끝.
